01 — Overview

What is AEGIS?

AEGIS (Autonomous Engine for General Intrusion Suppression) is a Python-based security operations agent. It runs continuously in the background, watching your system the same way a human security analyst would — except it never sleeps, never misses a packet, and acts in seconds.

Unlike traditional security tools that only alert you after something happens, AEGIS follows a detect → reason → respond loop. Before taking any action, the agent generates a human-readable explanation of why it is doing what it is doing. This is the Reasoning Engine — the feature that separates AEGIS from a basic script.

Detect

Monitors CPU, RAM, network I/O, and raw TCP packets in real time. Flags anomalies the instant they cross defined thresholds.

Reason

Before every action, AEGIS prints and logs why it is acting. No silent kills. Every decision has a paper trail.

Respond

Four-tier autonomous response: passive log → alert → semi-auto block → instant kernel-level IP drop via iptables.

Design Philosophy

AEGIS was built around three principles that come directly from the Manus agentic architecture:

  1. Modular — each file does exactly one job. Swap or upgrade any module without touching the others.
  2. Explainable — every automated decision is logged with a reasoning string before it executes.
  3. Cross-platform — runs in full live mode on Linux/Parrot OS; degrades gracefully to simulation mode on Windows.

Data Flow

All data flows in one direction: from the sensing layer → into the Brain → out to the action layer. The Brain never blocks — it uses a thread-safe queue so the Heartbeat and Sentinel can always keep running.

[ INPUT LAYER ]
   heartbeat.py   →  SystemSnapshot  →  terminal display + health log
   net_sentinel.py →  ThreatSnapshot  →  threat_queue (thread-safe)

[ BRAIN — aegis.py logic loop ]
   _logic_loop() drains threat_queue every 0.5s
   _handle_threat() → routes by risk level to the correct responder

     CRITICAL  →  _critical_response()  →  block_ip() immediately
     HIGH     →  _high_response()     →  5s countdown, then block_ip()
     MEDIUM   →  _medium_response()   →  log + watch
     LOW      →  _low_response()      →  passive log

[ ACTION LAYER — firewall.py ]
   Linux:   sudo iptables -A INPUT -s {ip} -j DROP  (real kernel block)
   Windows: [SIM] log the would-be action, return True     (safe simulation)

[ PERSISTENCE ]
   All events → logs/  (pathlib paths, works on C:\ and /home/)
03 — Module Reference

Module Reference

heartbeat.py — The Nervous System

core/heartbeat.py  THREAD: daemon

The Heartbeat is the first module to boot. It pulses every 10 seconds, samples system vitals, runs them through the ReasoningEngine, and emits a SystemSnapshot. It also writes every snapshot to logs/aegis_health.log as a JSON line.

Key Classes

HeartbeatCalls psutil every 10 seconds, feeds readings to the engine, displays results in the terminal, and logs to JSON.
SystemSnapshotA @dataclass holding one complete pulse: timestamp, CPU%, RAM%, net speeds, connection count, score, status, reasoning.

Note on permissions: The line psutil.net_connections(kind="inet") requires root on Linux to enumerate all process sockets. AEGIS wraps this in a try/except — it returns -1 for the connection count rather than crashing if run without sudo.

net_sentinel.py — The Eyes

modules/net_sentinel.py  THREAD: daemon  REQUIRES: root + libpcap

The Sentinel is a passive network sniffer. It uses the Scapy library to read raw TCP packets off the wire without interfering with any traffic. Its job is to detect SYN scans — the technique used by tools like Nmap to map open ports on a target machine.

How SYN Scan Detection Works

A SYN scan works by sending TCP packets with only the SYN flag set (no ACK). This is the first step of a TCP handshake — the scanner sends it to see if a port is open, but never completes the connection. AEGIS watches for this exact pattern:

Attacker sends SYN
→
Scapy captures packet
→
Filter: SYN=1, ACK=0
→
IP tracker updated
→
Port count ≥ 10?
→
ThreatSnapshot emitted

Key Classes

ClassRole
ThreatSnapshotDataclass: timestamp, attacker IP, list of ports hit, port count, risk level, threat type, reasoning, action taken, iptables-ready flag.
SentinelReasoningEvaluates an IP's port count. Returns risk level (LOW/MEDIUM/HIGH/CRITICAL), a reasoning string, and a recommended action.
NetSentinelOwns the Scapy sniff loop (runs in a daemon thread). Tracks ports per IP in a 5-second sliding window. Calls on_threat() callback on detection.

Risk Levels (Sentinel)

Ports HitRisk LevelRecommended ActionNmap Equivalent
10 – 24MEDIUMLOG_AND_WATCHSlow scan / script-kiddie probe
25 – 49HIGHALERT_AND_MONITORNmap -F (fast scan)
50+CRITICALFLAG_FOR_AUTOBLOCKNmap -sS (full stealth scan)

Alert Cooldown

Once an IP triggers an alert, AEGIS resets its port tracker and applies a 15-second cooldown for that IP. This prevents a single aggressive scan from flooding the logs with duplicate alerts.

Thread Safety

The Scapy sniffer runs on its own daemon thread (name="AEGIS-Sentinel"). All shared state (_ip_tracker, _port_tracker, _threats) is protected by a single threading.Lock. The on_threat() callback (which pushes to AegisCore._threat_queue) is called while holding the lock, ensuring the Brain always receives complete, consistent snapshots.

Configuration Constants

SCAN_WINDOW_SECONDS = 5    # Time window for counting port hits per IP
PORT_HIT_THRESHOLD  = 10   # Unique ports in window to trigger alert

firewall.py — The Fists

modules/firewall.py  CROSS-PLATFORM

The Firewall module is the action layer. It provides a clean Python API for blocking and unblocking IP addresses. Internally it detects the operating system at import time and routes every call to either a real iptables command or a simulation log.

OS Detection Logic

import platform

CURRENT_OS = platform.system()   # Returns: 'Linux', 'Windows', or 'Darwin'
SIMULATION = CURRENT_OS != "Linux"
SIM_LABEL  = "[SIM]" if SIMULATION else "[LIVE]"

This single boolean SIMULATION flows through the entire codebase. Every module imports it from firewall.py — there is only one source of truth for the OS mode.

Public API

FunctionSignatureDescription
block_ip(ip: str) → boolBlock an IP. Linux: iptables DROP. Windows: simulation log. Returns True on success.
unblock_ip(ip: str) → boolRemove an IP from the block list. Same OS branching as block_ip.
is_blocked(ip: str) → boolCheck if an IP is in the current session's block set.
get_blocked() → list[str]Return a sorted list of all currently blocked IPs.
dump_block_list() → NonePrint the full block list to the terminal. Called on shutdown.

Linux iptables Command

# Executed on Linux when block_ip(ip) is called:
sudo iptables -A INPUT -s {ip} -j DROP

# Executed on Linux when unblock_ip(ip) is called:
sudo iptables -D INPUT -s {ip} -j DROP

Important: iptables rules are not persistent across reboots by default on Linux. To make blocks permanent, install iptables-persistent (apt install iptables-persistent) and run netfilter-persistent save after AEGIS blocks an IP.

aegis.py — The Brain

aegis.py  ENTRY POINT

aegis.py is the master orchestrator. It is the only file you need to run. It boots all other modules, manages their threads, and owns the central decision loop.

AegisCore Class

MethodDescription
start()Boots the Heartbeat thread, boots the Sentinel thread (with full error handling), then enters the logic loop. Catches Ctrl+C and calls stop().
_boot_heartbeat()Creates a Heartbeat instance and starts it as a daemon thread named "AEGIS-Heartbeat".
_boot_sentinel()Attempts to import and start NetSentinel. Catches ImportError (Scapy not installed), OSError (Npcap missing on Windows), and any generic Exception. Logs the failure and continues — AEGIS does not crash without the Sentinel.

_logic_loop()Runs on the main thread. Every 0.5 seconds: acquires lock, drains the queue, releases lock, then calls _handle_threat() for each snapshot.
_handle_threat(snap)Routes by risk level: CRITICAL → _critical_response, HIGH → _high_response, MEDIUM → _medium_response, LOW → _low_response.
stop()Sets _running = False, stops the Sentinel, dumps the block list, logs the shutdown.

04 — Reasoning Engine

The Reasoning Engine

The Reasoning Engine is what makes AEGIS an agent rather than a script. Every module has its own ReasoningEngine or SentinelReasoning class that evaluates raw data and produces three outputs before any action is taken:

  1. A decision — what risk level or health score has been assigned
  2. A status — NOMINAL / DEGRADED / CRITICAL / etc.
  3. A reasoning string — plain English explanation of exactly why this decision was made

Example reasoning outputs from a live session:

# Heartbeat Reasoning Engine output:
→ CPU at 87.3% — exceeds 85% threshold.
  Possible cause: runaway process, crypto-miner, or DoS stress. |
  RAM at 78.1% — above comfortable range.

# Sentinel Reasoning Engine output:
→ 192.168.1.105 hit 52 unique ports in 5s.
  Pattern matches aggressive Nmap -sS full scan or automated exploit framework.
  Immediate block recommended.

The reasoning string is logged before the action executes — not after. This means even if a block fails (e.g. iptables returns an error), the reasoning for why the block was attempted is already in the log file.

05 — Threat Response

Threat Response Tiers

When NetSentinel detects a threat, it creates a ThreatSnapshot and passes it to the Brain via the callback. The Brain's _handle_threat() method routes the snapshot through one of four response paths based on risk level.

Risk Level Trigger Response Method Action Operator Control
CRITICAL 50+ ports in 5s _critical_response() Instant block_ip() — no waiting, no prompt None — fully autonomous
HIGH 25–49 ports in 5s _high_response() 5-second countdown → auto-block on timeout Press Enter during countdown to cancel
MEDIUM 10–24 ports in 5s _medium_response() Log to terminal and aegis_master.log Monitoring only — no block
LOW <10 ports _low_response() Passive log only No alert — background logging

The HIGH-Risk Semi-Auto Pattern

The 5-second countdown for HIGH-risk threats is implemented with a daemon input thread and threading.Event — AEGIS never blocks the main loop waiting for the operator. 

user_cancelled = threading.Event()

def wait_for_input():
    try:
        input()            # blocks in its own thread
        user_cancelled.set()
    except Exception:
        pass

input_thread = threading.Thread(target=wait_for_input, daemon=True)
input_thread.start()
input_thread.join(timeout=HIGH_RISK_TIMEOUT)   # 5 seconds

if user_cancelled.is_set():
    # Operator pressed Enter — skip block
else:
    # Timeout expired — auto-block
06 — Cross-Platform

Cross-Platform Design

AEGIS is designed to run on both Linux (Parrot OS, Ubuntu, Debian) and Windows. The platform detection happens once at import time in firewall.py and the result propagates throughout the system.

Linux / Parrot OS — LIVE mode

Full capabilities. Scapy sniffs raw packets via libpcap. iptables injects real kernel DROP rules. All modules active.

Windows — SIMULATION mode

Safe testing environment. Scapy requires Npcap — if missing, the Sentinel is skipped with a warning. All firewall actions are logged as [SIM] but never executed.

Npcap Fallback (Windows)

The Sentinel boot is wrapped in a full exception ladder so AEGIS never crashes on Windows, even if Npcap is not installed: 

try:
    from modules.net_sentinel import NetSentinel
    self._sentinel = NetSentinel(...)
    self._sentinel.start()
except ImportError:
    # Scapy not installed at all
    log("Sniffer unavailable on this host.")
except OSError as e:
    if "Npcap" in str(e) or "WinPcap" in str(e):
        # Scapy installed but no packet capture driver
        log("Npcap not found. Install from https://npcap.com")
    else:
        log(f"Sniffer unavailable: {e}")
except Exception as e:
    # Catch-all — never crash the agent
    log(f"Sniffer unavailable: {e}")

pathlib for Cross-Platform Paths

All log file paths use pathlib.Path. This means the same code resolves correctly on both systems without any manual path handling: 

BASE_DIR  = Path(__file__).resolve().parent
LOG_DIR   = BASE_DIR / "logs"           # Works on C:\ and /home/
AEGIS_LOG = LOG_DIR / "aegis_master.log"

LOG_DIR.mkdir(parents=True, exist_ok=True)  # Auto-creates logs/ if missing

Running AEGIS

Full Agent (all modules)

sudo venv/bin/python aegis.py

# Windows — simulation mode, no root needed
venv\Scripts\python aegis.py

Heartbeat Only (no root needed)

# Great for testing on low-privilege accounts
venv/bin/python core/heartbeat.py

Sentinel Only (standalone test)

sudo venv/bin/python modules/net_sentinel.py

Simulate a Port Scan Against Yourself

# In terminal 1 — start AEGIS
sudo venv/bin/python aegis.py

# In terminal 2 — fire a scan at yourself (ethical testing only)
nmap -sS 127.0.0.1

# AEGIS should fire a CRITICAL or HIGH alert within 5 seconds

Warning: Only ever run port scans against machines you own or have explicit written permission to test. Scanning third-party systems without authorization is illegal in most jurisdictions.

11 — Extending AEGIS

Extending AEGIS

AEGIS is designed to grow. Every module follows the same pattern: a class with a start()/stop() interface, a callback for emitting events, and a @dataclass for structured output. To add a new module:

  1. Create modules/your_module.py with a class that accepts an on_event callback.
  2. Define a dataclass for your event (e.g. ProcessSnapshot).
  3. In aegis.py, add a _boot_your_module() method following the same try/except pattern as _boot_sentinel().
  4. Push events onto self._threat_queue (or a new queue) inside the callback.
  5. Handle the new event type in _handle_threat() or a new handler method.

Planned Future Modules

12 — Glossary

Glossary

TermDefinition
SYN ScanA network reconnaissance technique (also called a stealth scan) where an attacker sends TCP SYN packets to many ports to discover which are open, without completing the handshake.
iptablesThe Linux kernel's built-in packet filtering firewall. AEGIS appends DROP rules to the INPUT chain to block attacker IPs at the network level.
ScapyA Python library for crafting and capturing raw network packets. AEGIS uses it in read-only passive mode to sniff TCP SYN packets.
BPF FilterBerkeley Packet Filter — a kernel-level filter that tells Scapy to only pass TCP packets to AEGIS, ignoring all other traffic for performance.
ThreatSnapshotA Python dataclass representing one detected threat event. Contains attacker IP, ports hit, risk level, reasoning, and recommended action.
SystemSnapshotA Python dataclass representing one Heartbeat pulse. Contains CPU%, RAM%, network speeds, health score, status, and reasoning.
Daemon ThreadA Python thread that automatically dies when the main program exits. Both the Heartbeat and Sentinel run as daemon threads so Ctrl+C cleanly stops everything.
Reasoning EngineThe class in each AEGIS module that converts raw metrics into human-readable explanations. Produces a reasoning string before every action.
Simulation ModeAEGIS's Windows-compatible operating mode. All firewall actions are logged with a [SIM] tag but no actual system calls are made.
NpcapA Windows packet capture driver required by Scapy to access raw network sockets. Equivalent of libpcap on Linux.
psutilA cross-platform Python library for accessing system utilization info — CPU, memory, disks, network, processes.
pathlibPython's built-in object-oriented filesystem path library. AEGIS uses it so all log paths work correctly on both Windows and Linux.
C2 / Command and ControlA server used by malware to receive instructions and exfiltrate data. An outbound traffic spike may indicate a compromised host communicating with a C2.
